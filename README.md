# 📈 Pocket Options Analyst

Бот для **Pocket Options (бинарные опционы)**: принимает скриншот графика и возвращает разбор:
**тренд → уровни → паттерны → сигнал (ВВЕРХ CALL / ВНИЗ PUT, экспирация) → сумма ставки → риски**,
плюс ведёт **журнал сделок со статистикой** (винрейт, break-even, P&L в $).

> Бинарный опцион не имеет стопа и тейка: результат решает цена на момент экспирации
> относительно цены входа. Поэтому сигнал выдаётся как **направление + экспирация**,
> а размер — как **ставка в % депозита** с учётом выплаты брокера.

Работает целиком на **Cloudflare Workers + Workers AI (vision)** — без серверов, без внешних платных API.

```
скриншот ──▶ Workers AI (Gemma 4, vision + thinking) ──▶ строгий JSON ──▶ расчёт позиции ──▶ UI
                                                                          └────▶ KV (журнал)
                                                                                 (если KV нет —
                                                                                  журнал в браузере)
```

---

## 🧠 Модель и качество анализа

Основная модель — **`@cf/google/gemma-4-26b-a4b-it`**: анализирует изображение
и работает с явно включённым **thinking** (`chat_template_kwargs.enable_thinking = true`).
Температура **`0`** у основной и резервной модели. Для Gemma выделено до **8192 токенов**
на рассуждение и итоговый ответ; анализ может занимать больше времени.
Если основная модель недоступна или не вернула JSON, используется **Llama 4 Scout**
(без native thinking). Фактически ответившая модель отображается под разбором.
`VISION_MODEL` в `wrangler.toml` позволяет переопределить модель; параметры thinking
отправляются только для указанной Gemma 4, чтобы не ломать другие endpoints.

Промпт требует проверить читаемость, таймфрейм, уровни, подтверждение свечами,
альтернативный сценарий и причины отказа от входа. При недостаточных данных — **нет сигнала**.
Это не специализированная торговая модель: превосходство по винрейту не измерялось.
Температура 0 снижает случайность, но не гарантирует одинаковые ответы, точность
или прибыль. Уверенность модели не является проверенной вероятностью выигрыша.

Поддержка vision и thinking сверена с [каталогом Cloudflare](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/workers-ai-models/gemma-4-26b-a4b-it.json).
Работа с реальным Workers AI требует отдельной проверки в аккаунте Cloudflare;
локальные тесты используют заглушки, а DEMO-превью не вызывает модель.

## 📓 Журнал сделок: два режима

| Режим | Когда работает | Где хранится |
|---|---|---|
| **Серверный (KV)** | привязан неймспейс `JOURNAL` в `wrangler.toml` | Cloudflare KV, доступен с любого устройства |
| **Локальный (браузер)** | KV нет **или** ключ доступа не введён/не подошёл | `localStorage` этого браузера |

Переключение автоматическое: если сервер вернул 503/401, интерфейс сам переходит
на локальный журнал и пишет об этом в статусе («журнал локально · …»).
Локальные сделки не синхронизируются между устройствами.

Чтобы включить серверный журнал:

```bash
npx wrangler kv namespace create JOURNAL
# выведет id — вставь его в wrangler.toml:
#   [[kv_namespaces]]
#   binding = "JOURNAL"
#   id = "ЗДЕСЬ_ID"
```

В CI это делает `scripts/ensure-kv.sh`. Если у токена `CLOUDFLARE_API_TOKEN` нет
прав на Workers KV Storage, скрипт напечатает причину отказа Cloudflare:

```
Cloudflare: [10000] Authentication error
→ похоже, у CLOUDFLARE_API_TOKEN нет прав на Workers KV Storage (Edit).
```

Что делать в этом случае (любой из вариантов):

1. Cloudflare Dashboard → **My Profile → API Tokens → Edit** у используемого токена →
   добавить право **Workers KV Storage: Edit** → сохранить. Следующий деплой сам
   создаст неймспейс и привяжет его.
2. Создать неймспейс руками: Cloudflare Dashboard → **Workers & Pages → KV →
   Create namespace** (имя, например, `chart-analyst-bot-JOURNAL`) → скопировать
   **ID** → GitHub → Settings → Secrets and variables → Actions →
   новый **secret или variable `KV_NAMESPACE_ID`** со значением id. CI подхватит его
   и допишет binding в `wrangler.toml` при деплое.

Пока KV не настроен, журнал автоматически работает локально в браузере — сайт
остаётся рабочим.

## ⚙️ Как считается ставка и результат

| Что | Формула |
|---|---|
| Сумма ставки | депозит × «ставка %» (минимум $1 на Pocket Options) |
| Выигрыш | ставка × выплата% (при выплате 85% → +$17 на $20) |
| Проигрыш | −ставка |
| Break-even винрейт | 100 / (100 + выплата%) (при 85% → 54.05%) |
| Результат сделки | CALL выигрывает, если цена на экспирации **выше** входа; PUT — если **ниже** |
| Ничья | цена не изменилась → 0 $ (проверь правило брокера) |

Предупреждения: ставка больше 5% депозита, выплата ниже 70%, ставка меньше $1.
Выплата вводится вручную — она меняется по активам и времени суток.

## 🧪 Локальный запуск и проверки

```bash
npm install
npm run preview      # локальный сервер на http://localhost:8787 (DEMO-режим, без Cloudflare)
npm run dev          # полноценный wrangler dev с Workers AI
npm run check        # smoke-проверки: интерфейс + математика + маршруты воркера
npm test             # check + тест scripts/ensure-kv.sh
```

`npm run check` состоит из четырёх быстрых тестов без сети:

* **`tools/ui-smoke.mjs`** — запускает скрипт интерфейса из `src/ui.js` с DOM-заглушками
  и падает, если страница не инициализируется (ловушка: любая ошибка времени
  выполнения в начале скрипта делает сайт «мёртвым»);
* **`tools/math-smoke.mjs`** — проверяет ставку, выигрыш/проигрыш, break-even,
  результат CALL/PUT и разбор ответа AI (экспирации, направление);
* **`tools/ai-smoke.mjs`** — проверяет температуру 0, включение thinking, форматы
  изображений и ответов, резервную модель и обработку ошибок;
* **`tools/worker-smoke.mjs`** — прогоняет реальные маршруты воркера
  (`/`, `/api/health`, `/api/analyze`, `/api/journal`, 401/404/OPTIONS) с заглушками AI и KV.

Эти же проверки выполняются в GitHub Actions перед деплоем (и на pull request'ах).

## 🚀 Деплой

Пуш в `main` → GitHub Actions сам деплоит воркер (см. `.github/workflows/deploy.yml`).
Нужные секреты репозитория: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`,
необязательные — `ACCESS_KEY` (ключ доступа) и `KV_NAMESPACE_ID` (id неймспейса журнала).
Ссылка на задеплоенный сайт попадает в Summary запуска.

## 🧭 Если сайт «выдаёт ошибку»

1. **`{"ok":false,"error":"Неверный ключ доступа."}` вместо страницы** — так было,
   когда проверка ключа стояла перед отдачей HTML. Сейчас страница отдаётся всегда,
   а ключ проверяется только на `/api/*`.
2. **Страница открывается, но кнопки/табы не работают** — ошибка времени выполнения
   в скрипте интерфейса; ловится `npm run check` (раньше это был
   `TypeError: $ is not a function`).
3. **Анализ не идёт, статус «Нужен ключ доступа»** — введи ключ в поле в шапке.
4. **«Серверный журнал недоступен … сделки сохраняются локально»** — либо KV не
   привязан к воркеру (см. раздел про журнал выше), либо ключ доступа ещё не введён. Проверить
   состояние можно запросом: `curl https://chart-analyst-bot.prachkevich19.workers.dev/api/health`
   — `"journal": true` означает, что серверный журнал работает, `"auth": true` —
   что сайт требует ключ.
5. **«Модель не вернула корректный анализ»** — Workers AI не разобрал скриншот:
   нужен более чёткий график (или проверь, что Workers AI включён в аккаунте).
